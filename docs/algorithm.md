# Algorithm and guarantees

Selectivity uses complement-based delta debugging. Start with the ordered list of units, partition it into two chunks, and try deleting each chunk. Keep a deletion only after every configured observation returns interesting. If no deletion works, split more finely. Finish at singleton deletions, restarting after every acceptance. Empty candidates are tested when the last unit is removed. An empty starting input is checked at baseline and final verification.

Units come in up to three levels. Lines keep their newline. A token is a run of non-whitespace bytes with the whitespace after it (space, tab, newline, carriage return, vertical tab, form feed), and leading whitespace is its own token. A character is one UTF-8 code point, or one byte where the data is not valid UTF-8. Each level is split from the current best text, so its units always join back to exactly that text. With `--units` set to tokens or chars, a round runs the line pass, then the token pass, then the character pass if chosen, and rounds repeat until one changes nothing; that final round's singleton checks show no single unit at any chosen level can be removed. With `--units=lines` there is one pass, as in 0.1.

With `--jobs N`, each step's complement candidates are checked in groups of up to N at once. After a group finishes, the earliest interesting candidate in candidate order is accepted, which is exactly the candidate a sequential run would accept, because every earlier one in the group was checked and was not interesting. That equivalence assumes the budget holds out: speculative checks spend budget, and with repeats above 1 a later check in a group can take the last executions before the candidate a sequential run would accept has finished its own, in which case the run stops incomplete rather than accepting it. Checks in the group after the accepted one (or after the first failed check) are logged as speculative and ignored. A speculative check's unresolved outcome does not withhold `locally_minimal`, since it never influenced the result. The execution budget is reserved before each run starts, so parallel checks never exceed it; a group can be cut short by the budget, and the first error in candidate order ends the run as before.

For directory input, the outer loop reduces files, optionally reduces the text in each remaining file at the chosen levels, and repeats until the input hash stops changing. A full unchanged loop establishes a deletion fixed point for both selected unit types. Every accepted deletion strictly reduces the number of units in that pass, so termination follows for finite input and terminating predicates. Tests can grow quadratically for difficult inputs; max-tests bounds executions, not bytes or wall-clock duration.

The initial snapshot stores file names, bytes and permissions, and the directory tree. Predicate changes to disposable candidates do not enter this model. SHA-256 digests identify the modeled input, rather than a compressed archive or the raw bytes of one file. Directory paths and file boundaries contribute to the digest.

No globally minimal claim is made. Predicate observations are finite; repeatability is a setting, not a proof. Unresolved results never justify deletion and prevent a locally_minimal claim. On incomplete runs, reduced holds the latest checkpoint and must not be treated as finally verified. Write or storage failures can leave partial artifacts; summary/report errors are returned to the caller.
